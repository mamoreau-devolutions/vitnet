# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

The explorer is a browser surface distributed by a Rust CLI, not a hosted service.

## Users

Developers investigating NativeAOT output, including very large applications.
They need to connect measured contributions to source, generated code, resources,
and compiler retention evidence.

## Product Purpose

Make size evidence understandable and navigable without loading an application
or its complete dependency graph into the browser.

## Operating Context

The existing CLI imports local evidence and produces versioned reports. Immutable
attribution and DGML indexes remain the authorities. Methods, Types and Blobs are
additive; resource, metadata and generic projections can overlap those budgets.

## Capabilities and Constraints

- Keep all application evidence local; do not execute application code.
- Bound browser data, rendering, backend work and responses independently.
- Preserve provenance, unknowns, candidate associations and partial-query stops.
- Retention witnesses are not predictions of reclaimable bytes.
- Preserve existing CLI behavior, graph generations and named-pipe services.
- Assumption: distribute a self-contained developer workbench with no separate
  frontend installation. The user was unavailable to confirm this choice.

## Evidence on Hand

Versioned local attribution reports, complete streamed identity caches, source
candidates, resource inventories, comparisons and bounded incoming graph queries.
The repository contains synthetic fixtures. Large private corpora remain outside
version control and must not be embedded in project assets or examples.

## Product Principles

1. Explain contributions before decorating them.
2. Distinguish ownership, emission, retention and amplification.
3. Make budgets and uncertainty visible.
4. Investigate a small working set; never pretend to visualize the whole graph.
